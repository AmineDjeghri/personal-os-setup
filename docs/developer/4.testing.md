# 4. Testing

Verify safe local behavior, artifacts and coverage; required CI checks platform integration separately.

## Local checks

1. Prepare once: `make install-dev`, then `make pre-commit-install` for git hooks.
2. Run `make test-local` (`make test` is an alias): unit and isolated deployment suites,
   four xdist workers by default (`N=1` for debugging). Plain `pytest` uses these same safe
   discovery paths. Empty collection is an error.
3. Run `make test-all`: safe suites, a complete matching wheel/sdist pair and isolated wheel
   installation. The smoke checks the exact version, console callable, package catalog, TUI
   stylesheet and required bundled chezmoi files. It never starts the application.
4. Run `make check`: static/docs hooks, then `test-all`. The docs hook calls `make docs-build`;
   the aggregate does not build the site twice. Checks do not install hooks or synchronize dependencies.
5. Run `make test-coverage` for separate Python coverage (`reports/coverage.xml`). It reuses
   `test-all`; coverage is not proof that OS integration ran. Establish a baseline before adding a threshold.

Initial measured line-coverage baseline (macOS, Python 3.14.8): **60%**, with **195 passing safe cases**.
Command-stub subprocesses and the isolated wheel smoke are validated separately from that measurement.

`tests/README.md` maps the suites. Frontend tests use a synthetic catalog, actions and managed
paths. System and release tests use temporary trees and command stubs; parallel tests share no state.

## Platform validation

| Suite                           | Required hosted runners                    | Boundary                                                  |
|---------------------------------|--------------------------------------------|-----------------------------------------------------------|
| self-contained + wheel smoke    | Ubuntu, macOS, Windows                     | POSIX deployment/shell fixtures skip Windows              |
| integration                     | Ubuntu 26.04, macOS latest, Windows latest | Linux/macOS mutate disposable hosts; Windows is read-only |
| CachyOS integration             | none                                       | not exercised by hosted CI                                |
| Arch container                  | manual                                     | interactive sandbox, not an integration pass              |

`make test-integration` runs serially and requires at least one passing test. Other operating
systems' skips remain allowed. Empty, all-skipped and failing runs fail; `--collect-only` is only
a diagnostic. Never run host-mutating integration or the manual container without explicit authorization.

A local `make check` pass establishes local validation only. Full required hosted validation
needs all static/docs, self-contained and integration CI jobs. `make act` launches those workflows
and is not a safe substitute for `test-local`.

## Static and documentation hooks

| Hook                     | Check                                                          |
|--------------------------|----------------------------------------------------------------|
| pre-commit-hooks         | syntax, whitespace, line endings, conflicts, test names        |
| ruff / ruff-format       | lint and format                                                |
| detect-secrets           | credentials, with narrow generated-content exceptions          |
| markdownlint / codespell | Markdown style and spelling                                    |
| uv-lock                  | lock matches project metadata                                  |
| skills-check             | repo-scoped agent skill links                                  |
| mkdocs-build             | `make docs-build`, strict links and anchors                    |
| actionlint               | workflow syntax, expressions and shell checks                  |
| commitizen               | message format at the commit-msg stage only                    |

zizmor, pip-audit and bandit remain disabled. The configuration-payload Markdown exclusion stays:
it contains templates and third-party material, not only authored documentation.
