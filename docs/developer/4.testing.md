# 4. Testing

Check a change before pushing it. CI runs exactly the same targets (local pass = CI pass).

## Commands

```bash
make check              # the CI gate: every hook + test-all + docs-build
make test-all           # every self-contained suite: unit, skills, built-wheel install smoke
make test               # unit tests only (tests/unit), 4 workers; make test N=8 for more
make docs-build         # strict documentation build (fails on broken links and anchors)
make pre-commit         # every hook below, on all files
make act                # run the GitHub workflows locally (Docker)
```

`make test-integration` drives real package managers (apt, pacman, brew): it runs in CI only,
never on your machine. To try the setup end to end, use a disposable VM: `make vm-cachyos`,
`make vm-ubuntu-server`, `make vm-ubuntu` (see the `vm-lab` skill).

## Writing tests

- One file per module: `tests/unit/test_<module>.py` (the `name-tests-test` hook checks the name).
- Tests run in parallel (pytest-xdist): no shared state; use `tmp_path` and `monkeypatch`.
- Never call a real package manager or `sudo` in a unit test: mock the manager.

## What `make pre-commit` checks

| Hook                                      | Checks                                                                                         |
|-------------------------------------------|------------------------------------------------------------------------------------------------|
| pre-commit-hooks                          | YAML/TOML/JSON syntax, whitespace, line endings, large files, merge conflicts, test file names |
| ruff, ruff-format                         | lint and format                                                                                |
| detect-secrets                            | no credential in a file                                                                        |
| markdownlint-cli2, codespell              | Markdown style and spelling                                                                    |
| uv-lock                                   | `uv.lock` matches `pyproject.toml`                                                             |
| skills-check                              | every skill in `.claude/skills/` has its `.agents/skills` link                                 |
| mkdocs-build                              | the documentation builds strictly (broken links and anchors fail)                              |
| commitizen (on commit, `commit-msg` hook) | commit message format                                                                          |

actionlint, zizmor, pip-audit and bandit are present in `.pre-commit-config.yaml` but commented out.
