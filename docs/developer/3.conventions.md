# 3. Conventions

The rules every change follows.

## Code

- Python, ruff (format and lint), Google docstrings: they generate the API reference
  (mkdocstrings).
- Run things with `make` targets (`make help`): CI runs the same ones.
- Logging with loguru (`from loguru import logger`). Log, then raise:

    ```python
    if not path.exists():
        logger.error(f"File not found: {path}. The current directory is: {Path.cwd()}")
        raise FileNotFoundError(path)
    ```

    In a loop, log and continue instead of raising when one failure must not stop the others.

- System-changing actions (installs, `chezmoi apply`, drivers, `sudo`) always go through the
  TUI's confirmation dialog.
- Use uv for everything (environments, runs, builds). For large data, Polars; for CPU-bound work,
  a `multiprocessing` pool.

## Branches and pull requests

1. Branch off `main`: `feature/<name>` or `bugfix/<name>`. (The `dev` branch is retired;
   `dev-release.yml` only runs if a `dev` branch is pushed again.)
2. Keep your branch up to date: `git merge main` if already pushed, `git rebase main` if not.
3. Before pushing: `make check` (lint, every self-contained suite, strict docs) and
   `make pre-commit` ([4. Testing](4.testing.md)).
4. Open a pull request to `main`. Its **title** follows the commit convention: it becomes the
   squash commit and decides the version.

Pull requests are squash-merged. Never edit `project.version` or create a tag by hand:
semantic-release does both ([5. Release](5.release.md)).

## Commit convention

`[emoji] <type>[(<scope>)][!]: <description>`, the emoji is optional
([Gitmoji](https://gitmoji.dev/)).

| Emoji                | Type                                                        | Aliases                   | Release | Example                                |
|----------------------|-------------------------------------------------------------|---------------------------|---------|----------------------------------------|
| 🐛                   | `fix`                                                       | `bugfix`, `hotfix`        | patch   | `🐛 fix(tui): handle a missing distro` |
| ⚡️                   | `perf`                                                      | —                         | patch   | `⚡️ perf(cache): reduce install time`  |
| ✨                   | `feat`                                                      | `feature`                 | minor   | `✨ feat(wsl): add a GPU check`        |
| 💥                   | `feat!`                                                     | `BREAKING CHANGE:` footer | major   | `💥 feat!: new packages.yaml schema`   |
| ♻️ 📝 🎨 🧪 🔧 👷 📦 | `refactor`, `docs`, `style`, `test`, `chore`, `ci`, `build` | —                         | none    | `📝 docs: update the WSL guide`        |

Scopes are optional (`github`, `tui`, `wsl`, `chezmoi`, `ci`, `deps`...). A breaking change is
either `!` after the type or a `BREAKING CHANGE: <what changed>` footer.

## Dependencies (Renovate)

- Renovate (`.github/renovate.json`) opens pull requests with a 7-day cooldown; security fixes come
  as standalone pull requests, immediately.
- PyPI dependencies are not pinned in `pyproject.toml`: `uv.lock` makes builds reproducible.
- Review every Renovate pull request; a dependency dashboard issue lists the pending ones.

## Secrets

- Never write a credential to a file of this repository, even untracked: **this repository is
  public**.
- `detect-secrets` runs as a pre-commit hook. For a line that intentionally references a secret
  placeholder (`${{ secrets.X }}`), add `# pragma: allowlist secret`; use the hook's
  `--exclude-*` arguments only for recurring false positives, never to exclude a whole file.

Security tools: detect-secrets and Renovate (7-day cooldown) are active; actionlint, zizmor and
pip-audit are configured in `.pre-commit-config.yaml` but commented out.

## Environment variables

Adding, renaming or removing one, in the same change: `.env.example` (if a laptop needs it), the
workflow `env:` and a repository secret (if CI needs it), and the table of
[5. Release](5.release.md#credentials) if a release target reads it.
